# ADR-0017: Phase 1 foundation choices and verified pins

- **Status:** ACCEPTED (owner approval 2026-10-17, D-25/D-26). Evidence: `docs/engineering/PHASE1_VERSION_VERIFICATION.md`, `docs/phase1/PHASE1_REPORT.md`.
- **Date:** 2026-10-17
- **Decision register:** D-25, D-26

## Context
Phase 1 builds the application foundation on the pins recommended in `VERSION_RECOMMENDATION.md`, with Node.js 24 LTS selected by the owner and pre-lock verification required. These are the engineering choices made while doing so.

## Decision
1. **Verified pins, none replaced:** Python 3.14.8, Django 5.2.18, DRF 3.18.3, psycopg 3.3.6, PostgreSQL 18.6, Node.js 24.22.0, Next.js 16.4.2, React 19.3.1. Supporting tools were chosen from evidence: ESLint 9.39.5 (ESLint 10 breaks `eslint-config-next`'s plugins), TypeScript 5.9.3 (typescript-eslint supports `<6.1`), Vitest 4.1.12 with Vite 7.3.7.
2. **Reproducible builds:** hash-locked Python dependencies (`uv pip compile --generate-hashes`, installed with `--require-hashes`), `package-lock.json` with exact versions and `npm ci`, container images pinned by digest. An optional BuildKit secret supplies a CA bundle on TLS-intercepting networks; it is never baked into an image.
3. **Configuration:** environment variables only; settings split into base/dev/test/prod; production fails fast on a short or default secret key, empty host list or insecure cookies; HSTS is off by default and never `includeSubDomains`/`preload` (shared domain, OQ-01/OQ-10).
4. **Identity first:** a custom user model (uuid primary key, `citext` e-mail, account status) and staff role assignments exist before any other migration. Django 5.2 removed `CIEmailField`, so a minimal custom `citext` field is used. No `PermissionsMixin`/superuser bypass; admin access derives from active roles and the admin shell is read-only. Primary keys are immutable through database triggers.
5. **Permissions:** a registry of role → permission codes (Contributor, Editor, Administrator; no Publisher, D-23) with pure separation-of-duties policy functions implementing D-18/D-22; DRF denies by default; a test keeps the registry equal to `ROLE_PERMISSION_MATRIX.md`. A regression found by the tests (a denied decision being falsy) is covered by a dedicated test.
6. **Authentication foundation:** session cookies (database-backed while Redis is deferred), CSRF enforced on every unsafe request including anonymous ones, Argon2id hashing, uniform `invalid_credentials` with dummy hashing, status revealed only after correct credentials, per-IP and per-e-mail throttles on the database cache. Registration, verification and reset remain Phase 4.
7. **API:** versioned under `/api/v1/` without trailing slashes, one error shape with request id, OpenAPI generated by drf-spectacular (3.1) and checked against `docs/engineering/openapi/openapi.yaml` (operations, ids, statuses, schemas); the contract gained `getApiRoot`.
8. **Observability:** JSON logs with request ids and redaction of credentials/e-mail addresses; no query strings and no gunicorn access log; `/health/live` and `/health/ready` (fails closed without leaking detail).
9. **Frontend:** `tokens.json` is the single source (reference values plus the approved DEV-01…DEV-04 corrections); a generated Tailwind theme removes the default palette, radii and shadows; tests prove parity with the measured reference, WCAG contrast of every token pair and that nothing rounded/shadowed/gradient can enter; nonce-based CSP through `proxy.ts`; the API is called server-side over the internal network; the browser stays same-origin.
10. **Local infrastructure:** Docker Compose project `upnext-dev` with a local Nginx dev proxy mirroring path routing, hardening options, a loopback-only port, and a production-mode override that builds the real images. It is not a deployment configuration.
11. **Quality:** pytest (85 % coverage gate), mypy strict, ruff, Vitest, Playwright, axe, a documentation-consistency checker, a generated traceability matrix, and a secret scan over the tree and every commit (reviewed allowlist keyed by hash). The GitHub Actions workflow is authored and statically linted but **has not been executed**.

## Consequences
- Known limitations are recorded in the Phase 1 report (ESLint 9 flagged unsupported by npm; an unfixable dev-tool advisory chain through `braces`; official support pages unreachable for date re-verification; CI not yet run on GitHub; pixel-level visual regression not implemented).
- Later phases extend these foundations (workflow wiring, account flows, outbox, public pages).

## Alternatives considered
Node.js 26 (rejected by owner); ESLint 10 and TypeScript 6/7 (incompatible or unnecessary risk, evidence in the verification record); Redis/Celery (deferred, ADR-0004); a UI library or theme (forbidden by D-08).
