# ADR-0027: Search visibility: Indexing API outbox, sitemap index, landing pages, crawler policy

Status: PROPOSED (DRAFT until the owner approves; nothing here is enabled in production). Date: 2026-11-03. Branch: `ccr-a4d103e2-kra4dq`.
Builds on D-51 (search-engine rules, guides) and ADR-0004 (no Celery/Redis; database outbox), ADR-0021 (hardening).

## Context
The earlier SEO work (D-51, `SEO_READINESS_REPORT.md`) fixed metadata, JobPosting data, canonicals, robots, a single sitemap and three guides, and explicitly left four things out: the Google Indexing API, employer profiles in the sitemap (SEO-A13), place pages, and any monitoring. The brief for this change asks for those, plus a sitemap index, an explicit crawler policy and AEO/GEO content. It forbids promising indexing, rankings or AI citations, and forbids enabling production submissions, touching DNS, Search Console permissions, credentials or the VPS without approval.

## Decisions (proposed)
1. **Indexing API as a transactional outbox, off by default.** New Django app `seo` with one table, `seo_indexingnotification`. The existing `transition_recorded` signal (already used by employer notifications) queues a row inside the editorial transaction: `T07` publish/republish → `URL_UPDATED`; `T09` takedown, `T10` withdraw, `T11` expire, `T12` archive → `URL_DELETED`. The worker (`run_worker`, every housekeeping cycle) sends them. No Celery, no new service (ADR-0004). A receiver failure is logged and never blocks publication.
2. **Only supported pages.** The API is supported by Google for `JobPosting` pages. A listing is eligible only when its category is jobs, internships or graduate programmes **and** it states a place (the same rule the web app uses to emit `JobPosting`, mirrored in `seo/indexing.py::has_job_markup` and pinned by tests on both sides). Scholarships, tenders, grants, drafts, listings without a place, and every other address are never submitted.
3. **Present truth only.** The decision is taken again just before sending. A row that waited while submissions were off, or while the listing changed, sends what is true now (or is skipped as `not_eligible`, `already_removed`, `stale`). Rows older than `UPNEXT_INDEXING_MAX_AGE_DAYS` (7) are dropped, not sent late; the first submission after approval is the deliberate `indexing_backfill` command.
4. **Duplicates, quota, retries.** At most one open row per address (partial unique index). An open row of the same kind absorbs the request; the other kind switches it. A removal is not repeated after an accepted removal. Daily self-limit `UPNEXT_INDEXING_DAILY_LIMIT` (150, below Google's default allowance, which the owner must confirm in the Cloud console), batches of 20, removals first. HTTP 429 stops the batch and keeps every row; 401/403 are configuration problems (rows kept, attempts not consumed, the `indexing` job shows failed); 5xx and network errors back off 2, 4, 8, 16, 32 minutes (cap 6 h) then the row is `dead` after 6 tries; 400/404 are permanent.
5. **Credentials.** Service-account key from `UPNEXT_GOOGLE_SERVICE_ACCOUNT_FILE` (preferred) or `..._JSON`; never committed, logged, stored or returned by the API. RS256 signing uses `cryptography` (added to `runtime.in`, hash-pinned; nothing else moved). HTTP is the standard library, like `accounts.google`.
6. **Closed-listing page lifecycle is unchanged and compatible.** Expired and withdrawn listings stay `200`, `noindex`, no `JobPosting`, no apply actions, out of the sitemap (D-51 / OQ-20 default); archived and taken-down listings are `404`. Google accepts `URL_DELETED` for a `404`/`410` or a `noindex` page. They are never redirected to the home page.
7. **Sitemap index.** `/sitemap.xml` is an index (named in robots.txt). Files: `pages`, `employers`, `jobs-N` (JobPosting categories), `opportunities-N` (scholarships, tenders, grants), `N` = chunks of 10,000 (`UPNEXT_SITEMAP_CHUNK`). `lastmod` is only ever a real date (last publication, profile approval, a guide's last edit, newest listing on a landing page); static pages carry none. One cached API feed (`/api/v1/sitemap`, additive fields) replaces the per-category list requests.
8. **Landing pages.** `/locations/<slug>` for active cities and provinces, and `/remote-jobs`. Indexable and in the sitemap only from **3** open listings (`MIN_LANDING_LISTINGS`); below that the page is valid for visitors, `noindex, follow`, with an honest empty state. A list narrowed to one place canonicalises to its landing page. Combinations of filters are never indexed. Sector/occupation pages are **not** built (OQ-38).
9. **Crawler policy** in `lib/crawler-policy.ts`, one source for robots.txt, llms.txt and tests: search and answer crawlers allowed; training-only crawlers disallowed by default, reversible by configuration (OQ-36). `/llms.txt` is added as an experimental convenience; it guarantees nothing.
10. **Monitoring.** Administrator-only, read-only page `/workspace/seo` over `GET /api/v1/staff/seo` (permission `settings.manage`). It keeps four things apart: queued, accepted by Google's API (HTTP 200: not indexing), Google's own indexed report (URL Inspection on a sample of at most 5 announced pages), and search impressions/clicks. Without a property or key it shows `setup_required` and no numbers; if Google refuses it shows the reason and the next step.
11. **Content.** A fourth guide (`/guides/common-job-seeker-questions`, DRAFT) answers the common questions in plain Q&A, from product behaviour only. No `FAQPage` markup (Google restricts FAQ rich results to a few authoritative sites). Listing pages show "Posted" and "Updated" dates. Source attribution is **not** reinstated: D-60 removed it; OQ-37.

## Consequences
- No migration touches existing tables; one new table. Rollback: set `UPNEXT_INDEXING_ENABLED=false` (default), or revert the branch.
- Production needs, before any submission: a deployed site (Phase 7), a verified Search Console property, a service account added as property **Owner**, the Indexing API enabled in the Cloud project, written owner approval, and `indexing_check` passing (it sends nothing).
- Nothing in this ADR claims ranking, indexing, rich-result eligibility or AI citation. It records technical correctness and what is still unproven.

## Alternatives rejected
- **Celery/Redis queue** (ADR-0004). **Google client library** (large dependency for one signed request). **Sending from the request** (publication would wait on Google). **Submitting every listing** (unsupported page types are a policy risk). **IndexNow** (still deferred; Bing reads the sitemap). **Redirecting expired jobs to the home page** (soft-404; forbidden by the brief). **Keyword "topic" pages** (thin).
