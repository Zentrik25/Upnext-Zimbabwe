# ADR-0006: Immutable internal identifiers and stable public slugs

- **Status:** ACCEPTED (owner approval recorded as D-13 on 2026-10-17). Document status of this record: DRAFT until the Phase 0 package is approved.
- **Date:** 2026-10-17
- **Decision register:** D-13

## Context
URLs are shared and indexed; titles change; ids must never be reused or edited.

## Decision
1. Every table uses an immutable `uuid` primary key generated by the application (version v4 vs time-ordered v7 chosen with the Phase 1 version pins, OQ-28); a trigger rejects id updates. `audit_event` uses a bigint identity as an ordered append-only log.
2. Listings are addressed publicly by **slug**: generated once at first publication from the title plus a 6-character random suffix; matches `^[a-z0-9]+(?:-[a-z0-9]+)*$`, 8–80 chars, unique; **never changed afterward** (trigger-enforced). Title corrections do not alter the URL.
3. The internal `id` is not a public handle; clients use slugs for pages and the detail endpoint. APIs that need an id (save, editorial) receive it from payloads.
4. Category codes and taxonomy slugs are immutable; taxonomy rows are deactivated, not deleted or renamed in place where a code is referenced.
5. Slug history/redirects are therefore unnecessary in Release 1. If a takedown-and-republish occurs, a new listing gets a new slug.

## Consequences
- Mistyped slugs cannot be corrected after publication (a deliberate trade-off for URL stability). Relaxing this requires a redirect table and a new ADR.
- Canonical URLs: `/opportunities/{slug}`; category path conventions are still OPEN (SEO review, IA).

## Alternatives considered
Slug derived live from title (rejected: URLs change); numeric auto-increment ids in URLs (rejected: enumerable, not stable across environments).


> **Amended by ADR-0025 (D-47):** a slug may be changed by an Editor or Administrator through transition T17; the old slug stays reserved and redirects permanently. Everything else here stands.
