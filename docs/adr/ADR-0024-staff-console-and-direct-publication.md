# ADR-0024 — Staff console (Next.js) and direct publication by staff authors — DRAFT

Status: DRAFT (recorded with D-46, implemented 2026-10-29). Not approved beyond the owner's written instruction of that date. It changes part of D-18/D-22 (the independent-approval rule) for one case and replaces the "Django Admin only" staff interface of P2-06.

## Context
The owner asked for a professional editorial CMS at `/staff/` built with the existing Next.js, Django REST and PostgreSQL stack in the design system of D-45, and for Administrators and Editors to publish staff-created listings without a second person's approval, while employer submissions keep moderation. The repository had no staff API (P2-06: "no editorial or administration API is exposed") and enforced independent approval in the service **and** in database triggers (migration 0002).

## Decision
1. **A staff JSON API, no new authority.** `apps/api/staffapi/` exposes `/api/v1/staff/*`: session and two-step proof, reference data, overview counts, opportunity list/detail/create/save/actions, organisations, employer claims, public reports, staff accounts, audit log, read-only settings. Each view authenticates the session, requires a registry permission (never a role name) and calls `opportunities.workflow`, `employers.services`, `reports.moderation` or `accounts.mfa`. The views are excluded from the public OpenAPI document and described in `docs/engineering/STAFF_API.md`.
2. **Two-step verification is unchanged and shared.** The staff API refuses every endpoint except the session and the two-step ones until the session carries the verified flag; the flag is set only after a valid code, in the existing session key, with the existing throttle and audit.
3. **Direct publication as an explicit, narrow exception.** `workflow.publish_direct` runs submission checks, the approval checklist and the publication in one transaction for the author of an open draft who holds `opp.publish_direct` and `opp.publish`. It flags the revision (`direct_publication`), records a review decision of the exact content hash and writes one `T07` event and one `opportunity.publish_direct` audit event marked direct and self-approved. A listing with an `EmployerListing` row is refused with `separation_of_duties`. Migration 0006 teaches the two database guards the same exception and nothing wider: flagged revision, author is the approver, active Editor or Administrator, no employer owner, matching hash; reviews of other kinds and every verification record still refuse the author.
4. **Editors become authors.** The Editor and Administrator roles gain the draft, submit, discard and amend permissions so they can use the editor; Contributors are unchanged. A draft is still edited only by its author.
5. **Django Admin moves to `/django-admin/`.** It keeps its two-step gate, session limits and Content-Security-Policy and stays available to administrators for taxonomies; edge routing sends `/django-admin/`, not `/staff/`, to Django. `/staff/` is served by Next.js with a per-request CSP nonce, `noindex` and no public header or footer.
6. **The editor writes only what the model holds.** Responsibilities live in the description (no separate column; OQ-06 is open), qualifications and experience come from the category schema's own fields, and skills are left untouched. Verification is displayed and recorded by someone other than the author; the editor records sources.

## Consequences
- One person can now make a listing live. Mitigations: the permission is limited to two roles, the checklist is attested and stored, every use is audited as direct, verification stays independent, employer content is excluded in code and in the database, and the audit log can be filtered for `opportunity.publish_direct`. The owner may later narrow it by removing `opp.publish_direct` from a role in `access/registry.py` and the matrix.
- Reports about a listing still cannot be decided by someone who wrote it (`reports.moderation.is_participant`), so a person cannot self-clear complaints about their own direct publication.
- The permission matrix document and tests that pinned "Editors cannot author" were updated (`test_workflow.py`, `test_admin.py`, `ROLE_PERMISSION_MATRIX.md`).

Alternatives rejected: letting any author skip review (not requested, removes the control for Contributors and employers); a database flag settable by the service alone without trigger changes (the triggers would refuse it, and a service-only rule would be the weaker design); keeping Django Admin at `/staff/` and building the console elsewhere (the instruction was `/staff/`); a second authentication system (not wanted).
