## 3. What the monitoring page shows (and does not)

| Figure | Meaning |
|---|---|
| Open job listings | Published, deadline not passed, category jobs / internships / graduate programmes |
| With valid JobPosting markup | Open job listings with no structured-data **error** (a stated place, a description) |
| Job listings in the sitemap / all listings in the sitemap | From the same query as the sitemap feed |
| Waiting, sent, failed, dead, superseded | Indexing API queue. **Sent = Google answered 200 to the notification**, not indexed |
| Last accepted submission, quota today, last run, oldest waiting | From the queue, `indexing_quota_day` and `core_jobrun` |
| Structured data errors and warnings | Errors: no JobPosting at all (`no_place`, `remote_without_country`) or a required property missing (`no_description`). Warnings: Google-recommended properties not stated (`no_deadline`, `no_employment_type`, `no_salary`). The page tells staff never to invent a value |
| Search Console | "Not connected" |

Retry: a `failed` or `dead` notification can be queued again (fresh attempts, audited as `indexing.retry`); refused with
`409 superseded` when a newer notification for the same address exists, and with `409 not_retryable` for any other
status. "Retry all dead" (audited as `indexing.retry_all`) skips superseded addresses. Queuing is not sending: the
worker sends only in `live` mode, within the quota, after re-reading the listing.

Permissions: `settings.manage` (Administrators only), checked on the server before anything is read; second step
required as for every staff endpoint. No credential, token, key path or response body is returned (tested).
